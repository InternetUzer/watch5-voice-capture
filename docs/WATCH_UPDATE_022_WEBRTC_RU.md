# Часы 0.2.2 — WebRTC VAD

Прежний пороговый детектор мог не запускать запись при тихой речи. В локальной
записи часов он заменён на нативный WebRTC VAD. Анализ идёт на часах без интернета,
Python и нейросетевой модели. Сохранённый WAV не фильтруется и не усиливается:
детектор только решает, какие интервалы сохранять.

## Поведение

| Чувствительность | WebRTC mode | Подтверждение начала |
|---|---:|---:|
| Высокая, по умолчанию | 0 | 20 мс положительного решения |
| Обычная | 1 | 40 мс положительных решений |
| Низкая | 2 | 60 мс положительных решений |

Старая настройка порогового детектора не переносится: новый ключ
`webrtcSensitivity` сначала принимает значение «Высокая» и затем сохраняет выбор.
Это приоритет полноты речи, поэтому возможны срабатывания на посторонний шум.
В обычном/низком режиме допускается промежуток до 40 мс между положительными кадрами.

- Вход: PCM16 LE, 16 кГц, один канал; WebRTC получает ровно 20 мс за вызов.
- Предзапись: последние 2 секунды перед срабатыванием.
- После последнего положительного решения VAD сохраняются ещё 5 секунд.
  У самого WebRTC также есть короткое внутреннее удержание, поэтому относительно
  физического окончания речи пауза может начаться немного позже 5 секунд.
- Файл: 10 минут **сохранённого аудио**, включая предзапись и хвосты; при СТОП
  сохраняется оставшийся короткий файл. Длинная тишина не входит в файл.
- Непрерывный режим обходит VAD, сохраняя индикатор уровня.
- Индикатор показывает уровень PCM в дБFS и решение «речь/ожидание».
  Это цифровой уровень микрофона, не измерение громкости помещения в дБ SPL.
  При отсутствии callback с аудио более 2 секунд появляется предупреждение.
- Удаление с часов по-прежнему только после подтверждения загрузки на Диск
  с совпадением имени, размера, SHA-256 и флагов проверки облачной копии.

Запись с наушников на телефоне использует Android-часть; этот патч меняет только
детектор локального микрофона часов. Android APK и сервер для него обновлять не нужно.

## Временные метки

Существующая схема сохранена: WAV содержит `vcap` с исходными временами каждого
сохранённого интервала, а сервер создаёт рядом `.timeline.json` на Яндекс Диске.
Поле `audio_start_ms` — позиция в склеенном аудио; `started_at_ms` — время исходной
записи. Поэтому после вырезанной тишины реальное время не вычисляется простым
прибавлением позиции проигрывателя к началу файла. Используются часы устройства,
UTC и сохранённое смещение часового пояса. Метки не озвучиваются внутри записи.
Обычный аудиоплеер не показывает эти метаданные как часы — для этого нужен
просмотр timeline или поддержка в проигрывателе/инструменте расшифровки.

## Обновление в DevEco

1. Остановить запись на часах. Не удалять приложение: установка поверх с прежней
   подписью сохраняет локальные записи и настройки подключения.
2. В PowerShell открыть корень **v2** и обновить ветку:

   ```powershell
   Set-Location 'C:\Users\Serega\DevecostudioProjects\watch5-voice-capture-v2'
   git status --short
   git pull --ff-only origin codex/voice-capture-v2
   ```

   Если Git сообщает о локальных изменениях, которые мешают обновлению, не
   выполнять reset/clean и не публиковать diff файлов подписи. Нужна аккуратная
   сверка изменённых файлов. Особенно сохранить локальный `watch/build-profile.json5`
   с подписью и игнорируемый `personal-setup.json`.
3. Открыть каталог `watch` в DevEco. Выполнить **File → Sync and Refresh Project**.
   Новый нативный модуль подключается из исходников, скачивать WebRTC отдельно не надо.
   В SDK должны быть установлены Native-компонент и инструменты CMake для выбранного SDK.
4. В конфигурации сборки `default` оставить прежнюю подпись. В модульном
   `entry/build-profile.json5` теперь есть `externalNativeOptions`; его нельзя
   заменять старой резервной копией без переноса этого блока.
5. Подключить часы, выбрать устройство и нажать Run. После сборки проверить,
   что устанавливается **подписанный** HAP, а на экране версия **0.2.2**.

## Проверка на Watch5

Сначала проверить прямой Wi-Fi, при необходимости временно отключив Bluetooth:
ранее пользователь подтвердил сбой сети часов через телефон. Это отдельная
проблема от обнаружения речи.

1. Авто, чувствительность «Высокая». Сказать обычную и тихую фразу с расстояния
   30 см, затем 1 м. Проверить начало слова в сохранённом WAV, не только счётчик.
2. Помолчать 10 секунд, произнести вторую фразу. Убедиться, что счётчик сначала
   останавливается, затем продолжается, а timeline сохраняет реальный разрыв времени.
3. Повторить с погашенным экраном и в условиях обычного рабочего шума.
4. СТОП, загрузка, проверка WAV и `.timeline.json` на Диске; только затем очередь
   на часах должна уменьшиться. Проверить также запись без интернета и последующую загрузку.
5. Проверить полный десятиминутный файл и короткий остаток после СТОП.
6. Сравнить разряд за одинаковые интервалы не менее часа при тех же Wi-Fi/BT,
   яркости/экране и звуковой сцене. WebRTC лёгкий, но микрофон работает и в ожидании;
   процент экономии батареи до замера на Watch5 неизвестен.

## Проверки разработчика

`python scripts/test-watch-vad.py --node-include /path/to/node/include`
собирает настоящие C/C++ исходники и Node-API мост на Linux, проверяет upstream
аудиофикстуру во всех четырёх режимах и запускает тесты политики, моста,
timeline, восстановления, relay и квитанций загрузки. Проверяется побайтовое
совпадение vendored-исходников с зафиксированными хешами.

Проверено 13.11.2026: нативная сборка на Linux успешна; эталонные решения
WebRTC совпали во всех 4 режимах; все 40 Node-тестов прошли, включая реальные
аудиофрагменты с амплитудой, уменьшенной до 25% и 10%.

Linux-проверка не заменяет ArkTS-компиляцию, линковку с HarmonyOS SDK, подпись
HAP и испытания микрофона/энергопотребления на физических Watch5. Эти этапы
выполняются в DevEco на компьютере владельца. Результаты на тестовой аудиофикстуре
не являются гарантией распознавания любой тихой речи в реальном шуме.

Лицензионные уведомления включены и в исходники, и в ресурсы HAP.
