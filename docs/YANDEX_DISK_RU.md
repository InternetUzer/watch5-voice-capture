# Архив аудиозаписей на Яндекс Диске

В версии 0.2.0 сервер умеет **принимать WAV по HTTPS и сразу отправлять в приватную папку Яндекс Диска**. Из часов используется прежний протокол; OAuth-токен Яндекса НЕ сохраняется на часах.

## Подключение Яндекс Диска

1. Войдите в нужный аккаунт Яндекса.
2. Создайте OAuth-приложение **Для доступа к API или отладки**: https://oauth.yandex.ru/client/new/
3. Выдайте приложению разрешение **Яндекс Диск: запись** (`cloud_api:disk.write`; для чтения содержимого через другой клиент дополнительно `cloud_api:disk.read`, если это действительно требуется).
4. Получите токен по официальной инструкции: https://yandex.ru/dev/id/doc/ru/tokens/debug-token .
5. Храните токен **только на сервере**, вне GitHub и файлов, которые вы кому-либо передаёте.

## Windows PowerShell — тестовый запуск сервера

```powershell
cd "C:\Users\Serega\DevecostudioProjects\watch5-voice-capture\server"
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:WATCH_API_KEY = 'длинный_ключ_для_часов'
$env:YANDEX_DISK_TOKEN = 'OAuth_токен_Яндекса'
$env:YANDEX_DISK_FOLDER = 'disk:/Watch5-Voice-Capture'
$env:WATCH_STORAGE_DIR = "$PWD\recordings"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В **другом** PowerShell проверка: `Invoke-RestMethod http://127.0.0.1:8000/health`.

## Подключение часов

В приложении на часах указать:
- `Server URL`: **HTTPS**-адрес вашего сервера с путём `/v1/recordings`.
- `API key`: значение `WATCH_API_KEY`, **не** токен Яндекс Диска.

После завершения записи нажать «Отправить файлы». Самостоятельный запуск выгрузки из фона **ещё не реализован**. `127.0.0.1` недоступен с часов; локальный сервер требует HTTPS-публикации с действительным сертификатом и постоянной доступностью. Не открывайте порт 8000 напрямую без TLS и аутентификации.

## Результат

На Яндекс Диске появляется приватная папка `Watch5-Voice-Capture`, в ней файлы вида `capture_1700000000000_0123456789ab.wav`.

- Если `YANDEX_DISK_TOKEN` не задан, запись остаётся **только локально** на сервере; в ответе `cloud_synced: false`.
- Если выгрузка в Диск не удалась, API возвращает 502, сохраняя WAV на локальном диске для повтора. Пока нет отдельного фонового обработчика очереди.
- Существующие ограничения: один файл до 8 МиБ, ручная отправка с часов, нет автоочистки архивов и автоматической расшифровки.

## Расшифровка в ChatGPT

Автоматического чтения личного Яндекс Диска из данного чата **нет**. Чтобы получить расшифровку, прикрепите WAV-файл сюда либо отправьте ссылку с доступом на чтение. Общедоступная ссылка означает, что по ней могут получить файл и другие люди.

Для полного цикла без участия человека нужен самостоятельный серверный конвейер (Yandex Disk API → STT/ИИ → база задач), а не обычная ссылка на Яндекс Диск.

Документация: https://yandex.ru/dev/disk/rest/ .
