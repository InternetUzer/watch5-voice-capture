**Владелец подтвердил: оставить текущую схему хранения.**

| Источник | Кто создаёт и хранит оригинал | Роль второго устройства |
| --- | --- | --- |
| Микрофон часов | Часы | Телефон может переслать готовый файл в интернет |
| Bluetooth-микрофон наушников, подключённых к телефону | Телефон | Часы управляют записью, показывают состояние, воспроизводят прямой звук |

как архив. Модель/производитель наушников не ограничиваются; нужен фактически доступный
Android аудиовход Bluetooth SCO/BLE. Микрофон телефона не подменяет его молча.

Целевые устройства: Huawei Watch5, прошивка **6.1.0.330 SP51**, Samsung S24 FE.

## 3. Пользовательская логика — сохранить при доработке

1. СТАРТ в AUTO: ожидание голоса, 2 секунды предзаписи, запись, ещё 5 секунд после речи.
2. Затем пауза внутри логического файла. При следующей речи запись продолжается.
3. После **600 секунд накопленного PCM**, а не 10 минут календарного времени,
   файл завершается и автоматически ставится в очередь загрузки.
4. СТОП прекращает запись и live-прослушивание; неполный остаток сохраняется.
   Последний файл, смена источника, авария или перезапуск могут дать файл короче 10 минут.
5. CONTINUOUS пишет без голосовых пауз. LISTEN сам по себе файлов не создаёт;
   прослушивание и запись могут быть включены одновременно.
6. Экран показывает фактический источник, состояние записи, накопленное время/остаток,
   очередь, прогресс загрузки и свободное место. Неподтверждённый СТОП не изображать успешным.
7. Нет интернета — оригиналы остаются на устройстве-источнике. При доступной сети
   загрузка повторяется; файлы часов могут передаваться через телефон посредством Wear Engine.
8. Удалять оригинал можно только по проверенной облачной квитанции для этого файла.
   «Телефон принял файл» и «запрос вернул 200/201» сами по себе недостаточны.
9. В WAV встроен `vcap` JSON; рядом на Диске — `.timeline.json`. Сегменты сопоставляют
   смещение в аудио реальным временам. В облачном имени начало в UTC; часовой пояс хранится
   в метаданных. Часы источников могут расходиться: синхронизацию времени проверить.

### Известные ограничения, которые нельзя скрывать в релизе

- После перезагрузки/системной остановки микрофон автоматически не включается:
  очередь восстанавливается, пользователь снова нажимает СТАРТ/включает помощник.
- Запись с системными индикаторами микрофона. Фоновую работу и screen-off проверить
  на целевой прошивке, обход индикации/разрешений не реализовывать.
- HarmonyOS WorkScheduler после завершения процесса управляет временем отправки сам;
  задан повтор раз в 2 часа, возможны дополнительные задержки. Мгновенная отправка при
  появлении сети гарантируется не во всех состояниях ОС. Android использует WorkManager.
- Детектор голосовой полосы эвристический, не обученный VAD; музыка/инструмент/ветер
  могут срабатывать. Есть три уровня чувствительности.
- При нехватке места остаётся резерв около 8 MiB, запись останавливается; несинхронизированная
  очередь не вытесняется. 10 минут PCM занимают около 19,2 MB плюс метаданные.
- Если телефон недоступен, часы не могут немедленно остановить его микрофон.
  Показать неподтверждённую команду; локальный СТОП есть в уведомлении телефона.
- После аварии точные временные отметки последней неполной секунды могут отсутствовать;
  такой файл отмечается `recovered: true`.

## 7. Подготовка сервера и OAuth

Команды ниже предназначены для shell пользователя u3653079. Перед выполнением сверить
пути с ISPmanager. Меняется только отдельный voice-сервис. Не запускать общий restart
Apache/nginx и не повторять bootstrap для уже настроенного основного сайта.

Сначала сохранить состояние. При изменённых tracked-файлах разобраться с ними,
не использовать `reset --hard` и `clean`.

```bash
set -eu
cd "$HOME/watch5-voice-capture"
test -z "$(git status --porcelain --untracked-files=no)"
umask 077
DEPLOY_BACKUP_DIR="$HOME/watch5-release-backups/$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$DEPLOY_BACKUP_DIR"
git rev-parse HEAD > "$DEPLOY_BACKUP_DIR/previous-sha.txt"
git archive HEAD > "$DEPLOY_BACKUP_DIR/source.tar"
cp -p "$HOME/.watch5-voice-capture.env" "$DEPLOY_BACKUP_DIR/server.env"
server/.venv/bin/python -m pip freeze > "$DEPLOY_BACKUP_DIR/requirements.freeze.txt"
printf 'Backup: %s\n' "$DEPLOY_BACKUP_DIR"
```

Отдельно сохранить текущие настройки именно voice-сайта, Passenger и его `.htaccess`,
если он используется. Не включать env/ключи в публичные артефакты. Существующие аудиофайлы
и журналы восстановления не удалять и не заменять резервной копией исходников.

В [Яндекс OAuth](https://oauth.yandex.ru/) владелец добавляет приложению чтение и запись
Диска, затем выдаёт **новый токен**. Добавление права в карточку не доказывает изменение
старого токена. Чтение требуется для проверки размера/хеша WAV и sidecar; scope охватывает
весь Диск, хотя сервер обращается к папке архива. Переход на `app:/` в эту ветку не входит.

Ввести токен в защищённой серверной форме либо через следующий ввод в доверенном SSH TTY
(без записи терминальной сессии). Скрипт запрещает fallback с видимым вводом:

```bash
cd "$HOME/watch5-voice-capture"
server/.venv/bin/python - <<'PY'
from pathlib import Path
import getpass, os, warnings
from dotenv import set_key
warnings.simplefilter('error', getpass.GetPassWarning)
path = Path.home() / '.watch5-voice-capture.env'
if not path.is_file():
    raise SystemExit('Existing protected env file is required')
token = getpass.getpass('New Yandex OAuth token (hidden): ').strip()
confirm = getpass.getpass('Repeat token (hidden): ').strip()
if not token or token != confirm or any(c.isspace() for c in token):
    raise SystemExit('Token was not changed')
os.chmod(path, 0o600)
set_key(str(path), 'YANDEX_DISK_TOKEN', token, quote_mode='always')
os.chmod(path, 0o600)
print('Token updated; value not displayed')
PY
```

Серверный env уже должен содержать действующий `WATCH_API_KEY`; не менять его без
одновременного обновления защищённых настроек обоих клиентов. Не выполнять `cat` env,
`printenv` или отладку HTTP-заголовков с секретами. Подробности: [YANDEX_DISK_RU.md](YANDEX_DISK_RU.md).

## 8. Развёртывание кандидата и сквозной тест

Следующий SHA — проверенный исходный серверный кандидат. Если кодер его исправил,
заменить на **точный проверенный SHA**, записать в отчёт; не подставлять плавающую ветку
и не считать ранее пройденные тесты проверкой новой версии.

```bash
set -eu
cd "$HOME/watch5-voice-capture"
test -z "$(git status --porcelain --untracked-files=no)"
git fetch origin codex/voice-capture-v2
CANDIDATE_SHA=59b2ea75fbe4be3df426c0578e39c3583e3a1d45
git checkout --detach "$CANDIDATE_SHA"
server/.venv/bin/python -m pip install -r server/requirements.txt
PYTHONPATH=server server/.venv/bin/python -m pytest -q server/tests
mkdir -p server/tmp
touch server/tmp/restart.txt
curl --fail --silent --show-error https://voice.metalcarcase.ru/health
server/.venv/bin/python server/scripts/smoke_upload.py \
  https://voice.metalcarcase.ru/v1/recordings --seconds 1
server/.venv/bin/python server/scripts/smoke_upload.py \
  https://voice.metalcarcase.ru/v1/recordings --seconds 600
```

Passenger может обслужить первый запрос старым worker после касания restart-файла.
Дождаться перезапуска и повторить контроль; `health=ok` проверяет доступность, не версию.
Не выдавать отсутствие `cloud_verified` за успех новой версии.

Успех полного теста: exit code 0, HTTP 201, `cloud_synced=true`, `cloud_verified=true`,
имя/байты/SHA-256 совпали; приватный WAV и `.timeline.json` доступны на Диске. Серверная
проверка должна сравнить `type,size,sha256` обоих файлов. Квитанцию не подделывать,
чтение метаданных не отключать ради обхода 403. При ошибках оригиналы сохраняются.

Проверить лимиты тела/таймауты только voice-vhost для 24 MiB; увеличивать их лишь при
подтверждённом ограничении панели. Проверить TLS, внешний доступ, отсутствие доступа
через HTTP к env/приватному каталогу. Зафиксировать отсутствие регрессии основного сайта.

Сервер сейчас сохраняет локальные копии WAV: автоматическая очистка после Диска не
реализована. До длительной эксплуатации определить квоту/мониторинг и политику очистки
**только проверенных** серверных копий. Час непрерывного PCM — около 115 MB; нельзя
допустить заполнение общего хостинга. Это отдельная доработка, не заявленная как готовая.

## 9. Настройка пары и аппаратная приёмка

Установить совместимую Huawei Health, привязать часы, настроить App ID и доступ Wear Engine.
В «Прораб+» → настройки → часы открыть помощник, указать публичный сертификат часов,
ввести ключ API в защищённое поле и разрешить связь Huawei Health. На часах указать
сертификат и **реальный package** Android, адрес API и ключ. Выдать разрешения микрофона,
Bluetooth и уведомлений. Включить помощник перед сеансом; без наушников он может делать relay.

| Проверка | Ожидаемый результат |
| --- | --- |
| Две реплики с минутой тишины | 2 с предзаписи и 5 с хвоста; один логический файл; точная временная шкала |
| 21 мин CONTINUOUS, затем СТОП | Два файла 10:00 и остаток около 1:00; без пропавших/повторных samples |
| LISTEN без записи | Звук на динамике часов, файлов нет; запуск записи не отключает live |
| 20+ мин с погашенными экранами | Фактическая фоновая работа, индикация, замер батареи и нагрева |
| Отключить интернет, накопить ≥2 файла | Очередь на источнике сохраняется; после загрузки удаляются только проверенные файлы |
| Часы без интернета, телефон с интернетом | Relay принимает копию; часы удаляют оригинал лишь после облачной квитанции |
| Сбой/403/timeout при загрузке; задержка метаданных | Нет ложного успеха и удаления; повторная загрузка не множит архив |
| Наушники отключить/подключить, телефонный звонок | Правильный фактический источник; нет скрытой записи микрофоном телефона |
| Одновременно СТОП и смена Bluetooth-маршрута | Запись не возобновляется после СТОП |
| Телефон потерял связь с часами | Архив на телефоне продолжается; UI часов не показывает устаревшее подтверждение |
| СТОП при разрыве связи | Явный статус «не подтверждён»; локальный СТОП телефона работает |
| Аварийно завершить процесс/перезагрузить | Восстановление `.part`/очереди, отметка recovered; новый микрофон только после СТАРТ |
| Низкая память | Остановка с сохранением очереди; никаких удалений несинхронизированных файлов |
| Обновить существующий release APK | Сохранились объекты/база «Прораб+», настройки, очередь и ключи |
| Основные функции «Прораб+» | Вход, объекты, журнал, файлы/DWG и текущие пользовательские сценарии без регрессии |

Для live измерить задержку и разборчивость, проверить эхо динамика часов и звук наушников
во время захвата. Если конкретная ОС не даёт нужный аудиомаршрут, показать ограничение,
не объявлять поддержку всех Bluetooth-устройств только по факту соединения.

## 10. Публикация и условия остановки выпуска

**Сначала** успешные OAuth/сервер, подписанные тестовые приложения, аппаратная приёмка,
полный Android CI и повторные серверные/Node-тесты. **Затем** интеграция PR и выпуск.
Версии сервера/клиентов и результаты проверок зафиксировать в одном release manifest.

В `.github/workflows/build.yml` публикация в Releases разрешена при наличии подписи
и работе на default branch. Merge Android PR может автоматически выпустить APK!
Поэтому не сливать PR #2 для проверки «соберётся ли». Сначала протестировать подписанный
артефакт feature-ветки; после всех критериев выполнить merge в проверенную целевую ветку.
Если нужна иная схема публикации, заранее перевести workflow на управляемый выпуск.

Выпуск остановить при любом из условий: HAP не собирается/не устанавливается; Wear Engine
не авторизует пару; неверный микрофон; потеря/удаление неподтверждённых записей; 403 на чтение
Диска; неподписанный release; нет фоновой записи; критические тесты не проходят.
Не публиковать широкому кругу пользователей функции, которые прошли только имитационные тесты.

## 11. Откат

### Сервер

Использовать сохранённый перед развёртыванием SHA, а не предполагать, что main остался прежним.
В той же shell-сессии переменная `DEPLOY_BACKUP_DIR` уже задана; при новой сессии указать
точный путь созданной резервной копии. Не трогать очередь и приватные WAV.

```bash
set -eu
cd "$HOME/watch5-voice-capture"
test -n "${DEPLOY_BACKUP_DIR:-}"
test -f "$DEPLOY_BACKUP_DIR/previous-sha.txt"
test -z "$(git status --porcelain --untracked-files=no)"
git checkout --detach "$(cat "$DEPLOY_BACKUP_DIR/previous-sha.txt")"
server/.venv/bin/python -m pip install -r "$DEPLOY_BACKUP_DIR/requirements.freeze.txt"
mkdir -p server/tmp
touch server/tmp/restart.txt
curl --fail --silent --show-error https://voice.metalcarcase.ru/health
```

Новый действующий OAuth обычно оставить. Env восстанавливать из закрытой копии только
при необходимости, сохранив 600; отозванный токен восстановлением файла не оживить.
Проверить загрузку по контракту возвращённой версии. Старый API не разрешает удалять
файлы v2-клиентов: очереди останутся до восстановления совместимого сервиса.

### Клиенты

Остановить запись кнопкой СТОП и сохранить очереди. Не удалять приложения и не очищать
данные ради downgrade. Обычное обновление поверх более высокого versionCode назад не
гарантируется; предпочтителен исправленный пакет со старым поведением и новым versionCode,
подписанный прежним ключом, либо предварительно проверенная процедура восстановления.
Публикацию ошибочного релиза остановить; работоспособную серверную версию оставить доступной.

## 12. Что кодер должен передать владельцу

- Ссылки на merged PR, точные SHA сервера/Android/часов и release manifest.
- Подписанный release APK и HAP, версии, SHA-256 файлов, инструкция обновления без потери данных.
- Подтверждение настройки App ID/сертификатов и прав OAuth **без самих секретов**.
- Отчёты полного CI и аппаратной матрицы: прошёл/не прошёл, устройства/прошивки, дата.
- Результат 600-секундного smoke: статус, размер/хеш, пути WAV/JSON, подтверждение локального удаления.
- Замеры фоновой работы, батареи и задержки live; честный перечень ограничений.
- Фактическая конфигурация production, путь закрытого backup и проверенный порядок отката.
- Короткая инструкция пользователю: включить помощник → СТАРТ на часах → режим → СТОП;
  где лежат оригиналы, как увидеть очередь и что делать после перезагрузки/разрыва связи.

Критерий завершения: обновление установлено поверх существующего приложения, связка проверена
на целевых устройствах, файл действительно найден и проверен на Диске, оригиналы удаляются
только после этого, основной сайт продолжает работать без изменений.
