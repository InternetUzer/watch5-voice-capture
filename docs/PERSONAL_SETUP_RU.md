# Личная сборка: серверный ключ и отпечаток без набора на часах

В личный HAP можно включить настройки и применить их при первом запуске после
обновления. Такой HAP содержит извлекаемый ключ API: его нельзя распространять.
OAuth Яндекса остаётся только на сервере; этот механизм принимает `WATCH_API_KEY`.
Обычная сборка без локального файла сохраняет прежний ручной ввод.

## Windows / DevEco

В терминале проекта `watch5-voice-capture-v2\watch`:

```powershell
git pull --ff-only origin codex/voice-capture-v2
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Set-PersonalSetup.ps1
```

Команда попросит **значение WATCH_API_KEY**, без имени переменной и кавычек.
Ввод скрыт; ключ не выводится в консоль и не попадает в историю команд.
ExecutionPolicy меняется только для запуска этого процесса.
Ключ берётся из закрытого серверного `~/.watch5-voice-capture.env`.
Секреты не отправлять в чат, GitHub или скриншоты.

Скрипт создаёт локальный `watch/entry/src/main/resources/rawfile/personal-setup.json`.
Файл и временные копии исключены из Git. На Windows/NTFS скрипт ограничивает доступ
к файлу текущим пользователем. Секрет остаётся в открытом виде в этом локальном файле
и в собранном HAP; защищённый ввод не шифрует их. Не применять `git add -f` к файлу.

Затем выполнить Sync и **Run** в DevEco при подключённых часах. Существующую подпись
сохранить и проверить `app.products[].signingConfig`: она должна ссылаться на её имя.
Не удалять приложение с часов: установка поверх сохраняет очередь записей.

При запуске ключ сохраняется в Asset Store, пакет и публичный отпечаток — в Preferences.
Настройки применяются один раз для ID профиля. Последующие запуски не перезаписывают
ручные изменения. Для сознательной смены ключа повторить скрипт и собрать обновление:
скрипт создаст новый ID. При ошибке сохранения профиль не считается успешно применённым.

После успешного импорта удалить локальный профиль:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Set-PersonalSetup.ps1 -Remove
```

Эта команда не удаляет ключ с часов и не изменяет уже собранные HAP. Для будущей
сборки без встроенного ключа выполнить Clean и собрать заново. Уже созданные личные
пакеты/их копии остаются секретными; при утечке сменить ключ на сервере и клиентах.

## Отпечаток «Прораб+»

Публичные значения находятся в `watch/config/companion-release.json`:

- Пакет: `ru.technadzor.app`.
- Проверенный APK: `prorab-plus-1.0.145.apk`.
- SHA-256 самого APK: `547952de3887128dc2af246a1a9018f08f1d2d9cb808e2b5cf6bfbdf765a5b4c`.
- SHA-256 **сертификата подписанта** (без двоеточий):
  `17CCD3055E66B7AE262761EE38A8E5C3B5184C4A0F81D8C93BC9BE239F0D03B0`.
- Источник: [артефакт сборки](https://github.com/InternetUzer/TECHNADZOR/actions/runs/42289826872/artifacts/13540735213).

Отпечаток извлечён из X.509-сертификата первого/единственного подписанта блока APK v2;
SHA-256 APK совпал с опубликованным ранее результатом CI. Это не хеш APK и не ID Huawei.
Другая подпись или debug-сборка требует другого отпечатка/пакета. Формат отпечатка
телефона — SHA-256 без двоеточий; это не формат отпечатка приложения часов.

## Что ещё требуется

Предзаполнение не регистрирует Wear Engine: нужны App ID Android-приложения,
доступ к Wear Engine и отпечаток приложения часов в настройках «Прораб+».
Проверенный APK 1.0.145 может не содержать настроенного Wear App ID; один отпечаток
не включает отсутствующую регистрацию и не делает помощник доступным в настройках.

На сервере нужна версия v2 и OAuth Яндекса с чтением/записью. Без проверенной облачной
квитанции часы сохраняют оригиналы. Добавление ключа автоматически запускает попытки
отправки очереди; это ещё не подтверждение загрузки или успешного удаления копий.

## Проверка изменений

Node-тесты проверяют однократный импорт, явную смену профиля, сохранение ручных
настроек, отсутствие секрета в ошибках и повтор после отказа Asset Store. Они не
заменяют компиляцию ArkTS и проверку защищённого хранилища на Watch5. Windows ACL
и PowerShell-скрипт требуют проверки на компьютере пользователя.
